# 提示词与模型任务能力联合验证

**日期：2026-11-11**

**状态：完成10场景、三批真实模型对照。最终候选同时保持整体缓存命中率95%以上，并减少失败工具调用；结论仅适用于本次 `deepseek-flash` 服务与这些场景。**

## 目标

本轮在[缓存95%联合报告](prompt-cache-95-2026-11-11.md)之后继续优化两类能力：

1. 在复杂代码修改中正确生成补丁、处理起始行和连续上下文，并在失败后有效恢复。
2. 扩展实际任务能力评估，覆盖无序输入、重叠／相邻区间、输入不可变性，以及多次尝试下的运行状态聚合。

同时记录整体／Turn 1／Turn 2+缓存命中率、具体token消耗和占比，避免只优化某一种已知错误。

## 评估配置

- 同一 `deepseek-flash`、Chat Completions兼容协议、128000窗口和8192输出上限。
- 每次运行使用独立临时工作区和HOME，显式拒绝 `exec`，不执行模型生成的命令。
- 通过最终文件、外部行为测试、实际工具结果和运行终态验收，不使用模型自述作为通过证据。
- 最终基线为旧程序两批60次运行；最终候选为三批90次运行，每批为10场景×3次独立重复。

新增能力场景：

| 场景 | 行为检查 |
| --- | --- |
| `code_intervals` | 无序区间、重叠与相邻区间合并、空输入、输入列表不可变及原有 `span` 行为 |
| `work_event_state` | 多次尝试后的终态、无终态的活跃运行、成功运行计数和原始run_id保持 |

既有8场景继续覆盖PLAN只读边界、直接补丁、Skill路由、逐项报告、多hunk补丁、范围注入、CSV聚合和长日志检索。

## 最终实现

### 补丁生成与恢复

- 将冗长重复的规则压缩为“复制连续上下文 → 分别计算旧／新行数 → 提交前核对”。
- 单行替换时，两个计数均等于hunk正文行数减1；多行增删继续分别计算，不放宽标准unified diff校验。
- `old_start` 来自最近读取的实际1-based行号；多hunk的 `new_start` 包含前序净行差。
- 对相距较远或多行增删的修改，优先每次只提交一个小hunk；成功后重读并使用新版本，而不是为减少调用而合并复杂修改。
- `patch_conflict` 错误同时提示上下文、起始行和前序行差，不自动接受无效补丁。

### Skill生命周期

- `skill_activate` 使用目录中的精确名称和SHA-256；激活后下一次请求自动携带文档。
- `skill_read_resource` 只用于已激活Skill的附加资源，不再作为激活前读取 `SKILL.md` 的替代路径。
- `skill_inactive` 错误明确指出下一步是调用 `skill_activate`。
