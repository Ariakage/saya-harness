# 项目范围与路线

## 已确认的定位

Saya Harness 是使用 Rust 构建的 Agent Runtime Harness。

Saya 负责驱动 Agent 循环：调用模型、处理工具请求、执行工具、提交工具结果，然后继续下一轮。首阶段交付 CLI，之后扩展 TUI 和 GUI。

CLI MVP 同时面向编程任务与通用任务，包含 PLAN、BUILD、CODE、WORK 四个可切换的工作模式，新会话默认 WORK。PLAN 负责需求分析与规划，BUILD 负责端到端实现和交付，CODE 聚焦代码编写、修改与调试，WORK 负责通用任务执行。

已确认的 MVP 能力还包括：

- CLI 提供交互会话与单次命令，分别支持持续对话和脚本调用。
- 权限有 `auto`、`bypass permissions`、`Manual Approval` 三种模式，默认 `auto`。
- PLAN 在三种权限模式下均只读调查并输出计划，不修改工作区文件。
- 用户手动切换工作模式，Agent 可以建议；当前调用完成后、下一次调用前生效，同一会话保留上下文。
- 接入 OpenAI Chat Completions、OpenAI Responses API、Anthropic Messages 三类模型协议。
- 提供本地文件读写、目录／内容搜索与命令执行工具。
- 本地保存会话，并支持列出和恢复。
- 恢复历史、原工作模式和配置引用后等待新输入，不自动重放工具；权限使用本次启动设置，不恢复历史授权。
- 提供流式交互、JSON 最终结果与 JSONL 事件输出。
- 单次命令支持显式预授权；需要确认但无法询问且未获授权时，返回需要确认并退出。

以上方向及下文 MVP 范围、验收和工程基础均已由项目负责人整套确认，见[完整基线](mvp-baseline.md) B-01 至 B-24、[决策记录](decisions.md) D-027、[工作模式](modes.md)和[执行契约](execution.md)。0.1.0 CLI 已发布。当前开发线已实现 N0 共享应用层与 N1 默认 TUI，后续增量及其验收范围见[开发进度](progress.md)。

## MVP 目标

让用户能够从 CLI 发起一个任务，并通过模型与工具之间的多轮交互得到结果。MVP 应覆盖实际的工具调用闭环，单次模型问答不足以验证这项核心能力。

首阶段确定包含：

- 为交互会话与单次命令提供一致的运行时行为。
- 提供四种模式的选择与用户切换入口，保持同一会话上下文并落实 PLAN 只读边界。
- 分别接入已确认的三类模型协议，完成模型与本地工具的多轮交互。
- 接入已确认的本地工具集，处理参数、执行结果与执行错误。
- 提供本地会话的保存、列出和恢复流程。
- 展示最终结果和必要的运行进度。
- 明确处理正常结束、运行失败、用户取消和运行限制。
- 提供无需真实模型 API 的核心循环验证方式。

编程与通用任务均已纳入产品范围。代表性任务与异常路径见[需求规格](requirements.md)和完整基线 B-23；实际使用的模型、服务地址和凭据由用户安装后配置，不是尚待选择的项目需求。

## 验收入口

| 场景 | 期望结果 |
| --- | --- |
| 模型直接回答 | CLI 展示回答，运行成功结束 |
| 选择运行模式 | 运行时与 CLI 展示的当前模式一致，并按该模式已确认的定义执行 |
| PLAN 只读调查 | 输出计划，工作区文件不被修改 |
| 切换工作模式 | 用户发起，当前调用完成后、下一次调用前生效；同一会话保留上下文 |
| 权限模式 | 分别按已确认规则执行；`bypass permissions` 跳过人工确认与路径限制，仍遵守 PLAN 只读 |
| 模型请求工具 | 执行选定工具，并把结果交回模型继续运行 |
| 三类模型协议 | 分别验证直接回答与工具调用闭环，不以其中一种协议的成功替代其他协议的验证 |
| 会话恢复 | 恢复历史、原工作模式和配置引用后等待新输入，不重放工具，不恢复历史授权 |
| 模型接入失败 | 用户获得可理解的错误，进程以失败状态结束 |
| 工具失败或参数无效 | 按明确策略返回工具错误或结束运行，无静默丢失 |
| 用户取消或达到限制 | 停止继续调度，完成资源清理并说明结束原因 |
| 重复验证核心流程 | 使用可控替身得到稳定结果，无需真实 API 密钥 |

## 演进路线

| 阶段 | 已确认的交付形态 | 范围 |
| --- | --- | --- |
| MVP | CLI | 交互与单次执行、三类模型协议、本地工具、四种模式、会话保存与恢复 |
| 后续阶段 | TUI | 在终端中展示多轮交互、执行状态与用户操作 |
| 后续阶段 | GUI | 复用运行时，提供图形化任务交互 |

首版工程选型、平台与交付规则已在完整基线 B-02、B-23 确定。TUI、GUI 是明确的后续阶段，不进入 0.1 的功能与排期承诺。

MVP之后，N0／N1已随0.2.0交付，N2的Sandbox、MCP与所需凭据基础，以及N3的插件生命周期、Hooks、上下文、检查点与全局记忆均已完成固定源码的四平台验收。N4 Goal已实现持久目标、证据、预算、手动与有限自动编排，并完成本机受控验收。当前开发线另提供由profile显式开启的图片、音频与视频输入。Browser、多Agent与远程执行等后续范围见[能力路线图](capability-roadmap.md)。D-033确认的约定目录Skill发现已纳入MVP，N3已扩展为显式Skill激活和本地插件管理。界面和运行时能力分别演进，本地会话保存与恢复和长期记忆分别维护。
