## 概念划分

以下概念用于描述交互与恢复，内部 Rust 类型名称由开发者处理，不再作为需求选择：

- **会话**：一段持续交互及其上下文，可保存、列出和恢复。
- **任务**：用户希望完成的一个目标，可以在同一会话中继续澄清或追加要求。
- **一次运行**：运行时针对当前输入推进模型与工具循环，直到完成、失败、取消或达到限制。
- **工作区**：默认启动 cwd，可用 --cwd 指定；文件范围、bypass 豁免和恢复重新关联见 B-09、B-12、B-20。
- **工作模式**：当前工作的职责与执行边界；同一会话可由用户切换，新会话默认 WORK。
- **权限模式**：操作如何取得执行许可，默认 auto；与工作模式分别配置。

保存会话不等于保存一个仍在执行的进程；恢复会话也不自动等于继续上次未完成的工具操作。

## 用户流程

### 交互会话

1. 用户启动 CLI，选择模型配置与工作区；新会话默认 WORK 与 auto，也可以显式选择其他模式。
2. 用户输入任务，Saya 展示当前工作模式、权限模式与必要的执行状态。
3. 运行时调用模型，按工具策略执行工具，并将结果交回模型。
4. Saya 输出结果、计划或需要用户补充的问题，用户可以继续输入。
5. 用户可请求切换工作模式；当前调用完成后、下一次调用前生效，保留上下文，后续操作遵守新模式边界。
6. 会话保存到本地，用户之后可列出并恢复。

命令语法、终端控制、模式状态与确认流程见 B-03、B-08、B-11。单次任务以 run 运行；交互入口为 saya／saya chat。

### 单次命令

1. 调用方提供任务、模式和必要配置；可显式预授权命令执行。
2. Saya 执行模型与工具循环，输出结果后退出。
3. 遇到需要确认但无法询问且未获授权的命令，返回需要确认并退出，不执行该命令。
4. 支持 JSON 最终结果与 JSONL 事件输出，通过 B-17 的固定退出状态区分结束原因。

任务通过 PROMPT、--prompt-file 或 --stdin 三选一提供。run 默认不交互，显式 --interactive 才可询问；--session 提交原会话的新输入，--approval-file 提供精确匹配的命令预授权。详细契约见 B-03、B-11、B-17，预授权不解除 PLAN 或显式 deny。

### 列出与恢复会话

1. 用户查看本地保存的会话并选择其中一个。
2. Saya 恢复历史、原工作模式与配置引用，使用本次启动的权限设置，等待新输入。
3. 不自动重放工具，也不恢复历史授权。
4. 如模型配置、工作区或会话数据不再可用，应提供可理解的提示。

列表字段、分页、关键状态保存、unknown、配置指纹变化及数据损坏均按 B-18 至 B-20 处理。恢复用已有工具消息闭合协议记录，不重新执行操作；异常路径见[执行契约](execution.md)。

## 四种模式的验收任务

以下夹具已由 B-23 确定；自动化替身验证运行时契约，真实模型质量另做手动联调。

| 场景 | 用户目标 | 预期交付 |
| --- | --- | --- |
| PLAN | 阅读示例 Rust 工程，分析功能实现方式 | 需求理解、必要澄清、步骤与验收计划；工作区文件不变 |
| BUILD | 从需求完成小型文本统计程序 | 必要实现、适用验证、产物与交付说明 |
| CODE | 修复该程序中的可复现缺陷 | 聚焦修改、必要验证及结果说明 |
| WORK | 将三份文本汇总为报告 | 形成报告，说明输入来源与处理结果 |

BUILD 的交付不默认包括提交、推送或外部发布；只有用户明确要求后，才按工具与权限规则处理。

## 执行规则与异常行为

以下原草案已按完整基线收敛为确定约束：

| 编号 | 行为 | 验证要点 |
| --- | --- | --- |
| EXEC-01 | PLAN 在工具调度边界只读且禁用 exec | 写入和通用命令被拒绝，无工作区修改 |
| EXEC-02 | 在执行前校验配置与输入 | 缺少必要配置时清楚报错，不执行工具 |
| EXEC-03 | 工具与模型失败返回对应结构化结果 | 不伪装成功，调用标识与结果成对 |
| EXEC-04 | 取消与预算停止调度并清理 | 进程组终止后等待 5 秒，再强制清理 |
| EXEC-05 | 工具不因框架重试而重复 | 模型重试有上限，工具由新调用显式提出 |
| EXEC-06 | 已知 API 凭据不落入会话与错误 | 只保存配置引用并对已知凭据脱敏 |
| EXEC-07 | 交互与单次命令复用运行时 | 相同模式、上下文与权限具有一致行为 |
| EXEC-08 | 派发前核对模式与许可 | 切到 PLAN 后旧写入不执行，失效确认不授权 |
| EXEC-09 | 流式工具参数完整并校验后执行 | 不依据半段参数启动工具 |

PLAN 使用原生只读文件／搜索与人工交互，不以命令名称或人工许可推断 exec 安全。会话恢复不自动重执行工具，见 SESSION-02。

会话保存、日志和缓存同样保持 PLAN 的目标工作区不变；数据目录与工作区重叠时报配置错误。

## MVP 验收条件

以下为已确认的验收条件；实际测试与限制见[验收证据索引](acceptance.md)，发行环境证据见[候选验证记录](release-validation.md)。

| 编号 | 条件 | 期望结果 |
| --- | --- | --- |
| AC-01 | 在交互会话连续输入两个相关任务 | 第二次交互能够使用前文上下文 |
| AC-02 | 通过单次命令提交一个可完成任务 | 按 B-03 输入、B-17 输出与退出；默认无交互等待 |
| AC-03 | 分别使用三类已确认模型协议 | 各自完成直接回答与一次工具调用闭环 |
| AC-04 | 在 PLAN 中调查项目并生成计划 | 得到计划，工作区文件内容与目录结构不因本次调查被修改 |
| AC-05 | 任意权限模式的 PLAN 出现写入或 exec 请求 | 工具拒绝结果与原调用关联，无工作区写入或命令派发 |
| AC-06 | Agent 建议从 PLAN 转为 BUILD | 建议本身不触发切换；由用户手动选择 |
| AC-07 | 用户在当前调用进行中请求切换工作模式 | 当前调用完成后、下一次调用前生效，保留上下文；后续操作遵守新模式边界 |
| AC-08 | 完成文本统计程序构建、缺陷修复与三份文本汇总夹具 | 分别得到实现及验证、修复结果与报告 |
| AC-09 | 保存后退出，列出并恢复会话 | 恢复历史、原工作模式和配置引用后等待新输入，不自动重放工具 |
| AC-10 | 模型或工具失败、用户取消、达到限制 | 按 B-16、B-17 返回状态与退出码，清理进程，不谎报成功 |
| AC-11 | 使用可控模型与工具替身验证核心流程 | 无需真实 API 密钥和付费调用，结果可重复 |
| AC-12 | 启动未指定模式的新会话 | 默认工作模式 WORK、权限模式 auto |
| AC-13 | auto 下规则无法形成最终结论 | 按需要进入模型核查，最后由用户兜底，不把无法判定当作已许可 |
| AC-14 | Manual Approval 模式下使用读、写、命令和后台控制工具 | 每次调用前取得人工许可；精确命令预授权可满足对应确认，未获许可时不执行 |
| AC-15 | bypass permissions 下访问原路径范围外目标 | 跳过路径与人工确认；PLAN 和显式 deny 继续生效 |
| AC-16 | BUILD 的模型调用结束前，用户请求切到 PLAN，模型返回写入请求 | PLAN 在工具派发前生效，该写入不执行 |
| AC-17 | 单次命令需要人工确认，但无法询问且未获授权 | 返回需要确认并退出，命令不执行 |
| AC-18 | 单次命令具备适用的显式预授权 | 对应确认要求可被满足，但不能以此突破 PLAN 只读 |
| AC-19 | 分别选择 JSON 最终结果与 JSONL 事件 | 严格符合 B-17 schema v1、字段、顺序、退出码，无日志污染 |
| AC-20 | 历史会话曾用 bypass 或获得过人工确认，以 auto 设置恢复 | 使用本次 auto 设置，不恢复历史权限或确认许可 |
| AC-21 | 当前调用中连续请求切换，或等待确认时切换 | 最后有效请求优先，确认失效并重查；取消优先 |
| AC-22 | 关键状态保存失败、崩溃或并发恢复 | 不在意图保存失败后执行工具，不重执行 unknown，写锁拒绝第二个写入者 |
| AC-23 | 会话含悬空工具调用后恢复并提交新输入 | 以对应终止结果闭合历史协议，不重新执行旧操作 |
| AC-24 | 按固定 workspace 与支持平台完成检查 | fmt、Clippy、测试与 release 构建通过，并具备所标注平台的 smoke 证据 |
