# 执行与恢复契约

**状态：基线已确认；各项能力的实际实现与验证状态见[开发进度](progress.md)。**

需求入口见[需求规格](requirements.md)，权威细节见[完整基线](mvp-baseline.md)，对应[决策记录](decisions.md) D-027。本文件汇总工作模式、权限、执行、输出和恢复之间的关系。

## 工作模式与权限模式

两者分别配置：工作模式描述做什么以及职责边界，权限模式决定操作如何获得执行许可。

- 新会话默认工作模式为 WORK；PLAN、BUILD、CODE、WORK 的职责见[运行模式](modes.md)。
- 默认权限模式为 `auto`，另有 `bypass permissions` 和 `Manual Approval`；CLI 参数分别为 `--permissions auto|bypass|manual`。
- PLAN 在三种权限模式下均保持只读调查，不修改工作区文件。
- 恢复会话时恢复原工作模式，但使用本次启动的权限设置，不从历史恢复授权。

## 三种权限模式

| 权限模式 | 已确认的执行许可规则 | 路径范围 |
| --- | --- | --- |
| `auto` | 规则先判断，必要时模型核查，最后由用户兜底 | 文件工具与命令 cwd 默认限于工作区及用户配置的 additional roots |
| `Manual Approval` | 每次工具调用前人工批准，包括读取、搜索和后台启动／状态／取消；模型请求不单独确认 | 文件工具与命令 cwd 默认限于工作区及用户配置的 additional roots |
| `bypass permissions` | 跳过人工确认 | 跳过路径限制；PLAN 仍只读 |

早期提出的“工作区文件读写自动、命令执行前询问”不再作为所有会话的统一策略，由上述权限模式分别决定行为。默认 `auto` 不等于无条件放行文件写入，也不等于每条命令都必须询问。

`auto` 使用 TOML 规则，deny ＞ask ＞allow；原生工作区读写默认 allow，未匹配的 exec 进入独立、无工具的核查请求。默认复用执行 profile，也可配置 review.profile；无法形成结论时由用户兜底。完整规则、核查字段与优先级见 B-10。

`bypass permissions` 放开路径范围并跳过人工确认与模型核查，但保留 PLAN 只读、用户显式 deny、参数校验、取消与运行预算。PLAN 禁用通用 exec。0.1／0.2 的发行范围保留无子进程文件系统隔离限制；当前 N2 开发线的原生执行边界见下节。

权限模式只允许在空闲时修改；运行中拒绝修改。它不沿用工作模式的调用边界切换规则。

## 运行中的工作模式切换

已确认的生效时机是：**记录切换请求，当前调用完成后、下一次调用前生效**。

运行时显式区分“当前模式”和“待切换模式”，界面分别展示：

1. 用户请求切换，记录目标模式；切换到 PLAN 时取消并清理后台写入及命令，其余已派发调用按边界完成。
2. 收到本次调用结果后，记录结果并应用待切换模式。
3. 在下一次模型调用或工具执行前，按新模式重新检查执行条件。
4. 已生成但尚未执行的工具请求，也必须按生效后的模式检查，不能继承生成请求时的权限。

例如：BUILD 的模型调用进行中，用户请求切到 PLAN。模型返回写文件请求时，PLAN 已在下一次调用前生效，该写入不能执行。若切换请求到来时写入已经执行中，则先完成当前调用；PLAN 的只读边界从实际生效时开始，不追溯撤销此前的操作。

同一会话保留上下文，切换不重置历史，也不意味着任务已完成。工具默认串行；显式后台任务可与模型及其他获准工具并发，逐次检查模式和权限。切入 PLAN 前取消并清理后台写入与命令；运行结束时清理所有未完成后台任务。具体实现状态见开发进度。

边界情况已经按 B-08 确定：

- 连续切换保留最后一个有效请求。
- 等待确认时可立即应用切换，使旧确认失效并重新判断。
- 取消优先，清理当前调用；最后请求的模式用于下一次输入，不自动启动运行。
- 当前调用失败或超时同样视为结束，应用待切换模式后按错误策略处理。

## 工具与人工确认

工具为 read_file、list_dir、find_files、search_text、write_file、apply_patch、exec，以及人工澄清用的 ask_user；后台控制工具为 background_start、background_status 和 background_cancel。核心输入输出见 B-14。

开发线按D-046增加 `todo_write` 会话任务清单工具，PLAN可更新任务元数据，Manual Approval每次调用均需批准。完整列表替换、校验限额及恢复规则见[运行时](runtime.md#会话任务清单)。

工具按下面的顺序处理：

1. 获取完整工具请求并校验工具名称、参数和目标。
2. 检查当前工作模式，落实 PLAN 只读边界。
3. 按权限模式执行规则判断、模型核查或人工确认。
4. 真正派发前检查模式与许可仍适用，再执行并返回结果。

确认展示工具、目标文件或完整命令、工作目录及当前模式，绑定规范化参数、cwd、工作模式与权限设置版本，只对一次操作有效。不持久化授权，也没有全局 yes 开关；变化后重新判断。

路径校验处理实际目标、相对路径、`..` 与符号链接；auto／manual 超出允许根直接拒绝，可由用户配置扩充根，bypass 跳过范围限制。PLAN 禁用通用命令执行，人工确认不能突破只读要求。

文件修改使用读取版本校验与单文件临时写入／替换，不提供跨文件事务。exec 直接接受 argv，默认 120 秒超时，stdout／stderr 各保留 64 KiB；取消后先终止进程组，5 秒后强制清理。完整限制与配置见 B-12 至 B-16。

## 单次命令与输出

已确认：单次命令允许用户显式预授权命令执行。若需要人工确认，但没有适用的预授权且无法询问用户，应返回“需要确认”并退出，不执行该命令。

预授权使用 run 的 `--approval-file PATH`，版本 1 JSON 中列出 commands 的完整 argv 与 cwd，精确匹配并绑定本次运行初始模式和权限设置；切换后失效。不解除 PLAN、显式 deny 或路径边界。

版本1预授权只匹配未覆盖命令环境的请求。模型提供非空 `env` 时，由当前权限流程核查或人工确认，原argv／cwd预授权保持可用。auto下的静态allow规则同样将环境覆盖交给独立核查，显式deny和ask继续优先生效。

`path_glob` 编译时规范化静态目录前缀及最长已存在祖先，使符号链接工作区与运行期真实目标使用同一基准。动态glob后缀保留原语义，包含父目录组件或悬空链接前缀的规则返回配置错误。

文本CLI的run、chat与导出入口处理INT、TERM和HUP信号。终止先触发取消并等待所拥有的运行和后台任务清理，会话锁保持到清理完成。重复INT沿既定强制退出规则处理，相关未知结果按恢复契约核查。

JSONL事件序号严格递增，预留可产生空洞。每个4096序号预留块保留末位供存储故障终态使用，终态沿当前会话和运行身份输出，sink故障沿输出错误结束。运行期失败退出1，输入预检失败沿用退出2。

输出为流式交互、JSON 最终结果与 JSONL 事件，schema_version 为 1。精确字段、事件 data 和退出码已在 B-17 确定：

| 输出方式 | 约定 |
| --- | --- |
| 交互文本 | 展示当前模式、待切换状态、必要进度与最终结果 |
| JSON 最终结果 | 标准输出为一个完整结果对象，不混入进度和确认提示 |
| JSONL 事件 | 标准输出每行一个完整 JSON 事件，包含最终状态，便于脚本逐行消费 |
| 诊断与提示 | 诊断写 stderr，人工交互使用控制终端，不占用任务 stdin 或污染 stdout |

完成／失败／配置错误／需要确认／需要输入／达到限制／取消分别使用退出码 0／1／2／3／4／5／130；状态字段使用 B-17 的固定值。run 默认不交互，显式 --interactive 才可向终端询问；流式工具参数完整前不能执行。

## 会话恢复

已确认的默认行为：恢复历史、原工作模式与配置引用，等待新输入，不自动重放工具。权限使用本次启动设置，历史确认不重新生效。

恢复流程如下：

1. 读取会话及其历史、工作模式、配置引用与工具执行记录。
2. 验证会话数据、模型配置引用和工作区是否仍可用。
3. 应用本次启动的权限设置；不恢复历史许可。
4. 展示恢复结果与必要的未完成状态，然后等待用户输入。

工具区分未执行、已完成和结果不明；副作用前保存执行意图，调用后保存结果。崩溃遗留的 running 记录为 unknown；保存失败停止后续调度。悬空工具调用补相应的终止结果以闭合协议记录，不重新执行历史操作。

| 异常情况 | 已确定行为 |
| --- | --- |
| 配置引用失效或缺少凭据 | 配置错误，不静默换服务，补齐后再恢复 |
| 工作区移动或不存在 | 使用 --cwd 显式重新关联，不猜测目录 |
| 同名模型配置已变更 | 协议／模型变化新建会话；相同协议与模型的其他指纹变化需 --accept-config-change，凭据轮换不算模型变化 |
| 上次命令执行中断，结果不明 | 展示状态，等待新输入，不自动重跑 |
| 历史中有待确认命令 | 仅恢复记录，不自动批准或执行 |
| 保存失败或会话损坏 | failed／storage_error 或 storage_corrupt，不静默重建或声称保存成功 |
| 多进程同时写同一会话 | 排他会话写锁，第二个写入者返回 session_busy，查询仍可读 |

会话库使用工作区外 XDG 数据目录中的 SQLite WAL，格式版本为 1，按关键状态事务保存，不自动过期或上传；配置、模型、工作区与工具状态随会话记录。日志位于 XDG state 目录。PLAN 与数据目录重叠时启动检查失败，不写入目标工作区。

## 模式事件与后台收尾

模式请求与实际生效分别产生 `mode.change_requested` 和 `mode.changed` 事件。运行时将待发事件和会话模式一起持久化，成功后才确认已保存前缀。运行内日志最多保留256项，预留挂起切换最终生效的空间，满时返回 `mode_event_limit`，调用方可在日志排空后重试。

后台任务接纳时即持有共享模式租约。切换PLAN先取消写入与命令，完成清理后才应用模式。非exec后台调用使用运行配置的工具超时，达到期限后取消并继续等待收尾，保存失败及已经发生的副作用仍按实际结果报告。exec继续使用自身超时和进程组清理。

## N2 原生执行边界

当前开发线默认采用 `sandbox.backend = "auto"`，macOS 选择独立 SeatbeltBackend，Linux 选择 Bubblewrap、Seccomp 与可选 socat 代理桥。实际准备、能力报告、命令和文件服务通过同一 ExecutionBackend 连接。配置加载与原生能力探测分别进行，完整四平台整体验收状态见[N2 验收记录](n2-validation.md)。

权限许可继续绑定规范化操作、模式、权限版本、环境摘要及执行环境身份。`bypass` 保留 PLAN、显式 deny、参数和预算规则，并继续受原生执行策略约束。宿主保护路径优先于可写根，默认包括启动时已存在的配置、data、state、cache 和工作区 `.saya/local`。活动凭据存储新建后会强制加入实际保护路径。

`sandbox.read_roots` 与 `write_roots` 控制 OS 视图，`permissions.additional_roots` 同时扩展逻辑文件权限和原生读写根。单独提供工具链可读根只允许进程访问该目录，文件工具访问仍按逻辑权限判断。解释器与编译器需要的额外目录由用户显式选择。

内置六种文件工具在同一原生后端包裹的私有 worker 中执行。宿主先持久化 intent 并消费一次许可，再传递确切调用、限额和已批准目标，worker 二次解析目标并检查 PLAN。请求与响应各有 32 MiB wire 硬上限，配置中的扫描、返回和写入上限继续按各自语义校验。损坏、超限、截断响应或进程异常按实际观测报告，副作用无法确认时保留 `unknown`。

命令的实际环境在隔离完成后通过专用私有 FD 恢复，宿主 launcher 使用固定最小环境。未声明 FD 在 exec 时关闭，受控传递的环境 FD 在 payload 前关闭。文件和命令共用进程组监督、超时、取消、输出排空及持久化结果边界，后台执行复用相同链路。

默认网络 `deny` 阻断原生工具直接外联。`proxy` 仅向本次宿主代理入口开放 TCP，由 HTTP／CONNECT broker 核查 origin、解析后的 IP 和连接限额。Linux 通过私有网络 namespace 内的 socat 桥接，macOS 使用 Seatbelt TCP 端点规则。HTTPS 隧道的主机／端口授权独立于加密方法和路径。

Linux 视图保留最小系统目录、工作区、显式根及私有临时目录，procfs 与其已检测别名不进入 payload 视图。Seccomp 拒绝危险命名空间、进程内存和内核入口，并限定 socket family。匿名 Unix 流式 pair 用于受控进程内部通信。macOS 使用系统 sandbox-exec，按规范化路径和受控 SBPL 参数配置。

显式 Host 兼容模式的文件／网络及聚合资源隔离报告为 `unsupported`，工作模式、许可和运行预算继续生效。Host 支持现有单进程 rlimit，显式 `cgroup_root` 或任一总内存／总进程数／CPU 带宽请求会在模型派发前以 `sandbox_capability_unavailable` 失败。存在私有凭据存储或启用 `credential_ref` 时应用继续拒绝 Host。

资源按 `hard`、`best_effort`、`unsupported` 分别报告。Linux 聚合硬约束要求 Bubblewrap 文件系统边界和有效 cgroup v2 委派。Linux 原生后端依据 mountinfo 拒绝所有与 `cgroup`／`cgroup2` 挂载存在祖先或后代交集的可写根，包含 bind 别名及委派根的兄弟路径，错误为 `unsupported_fs_policy`。默认工作区与 `permissions.additional_roots` 同样接受检查，显式只读 cgroup 根可按其余策略处理。macOS 后代进程清理保持 `best_effort`。

本轮资源配置修复的最终四平台验收待重跑。委派正向用例检查内核限值、活动成员和自有子组清理，负对照检查模型派发前拒绝，资源耗尽压力仍未验证。[资源验收边界](sandbox.md#资源与清理能力矩阵)

无法表示的文件策略、缺失的必需控制或清理无法确认均返回明确错误，原生后端继续保持失败关闭。完整参数见[配置](configuration.md#n2-原生隔离配置)，设计与平台边界见[原生隔离设计](sandbox.md)。

## N2 外部工具与服务收尾

MCP 工具由可信注册表命名和分类，服务器描述、annotations 及 schema 来自外部数据。只有宿主显式 `read_only_tools` 分类可使 HTTP 工具进入 PLAN。stdio 服务在 PLAN 中保持停止。Manual Approval 确认 stdio 启动及每次模型工具调用。目录代次变化使旧批准失效，执行前再次核对。

连接、鉴权、stdio 握手和每次目录发现使用运行共享活跃预算与相应配置超时。人工确认独立暂停活跃计时，清理阶段继续完成实际进程回收、连接关闭与 broker 释放。启动 intent 保存后、进程派发前再次检查预算，耗尽时记录已知失败。派发后握手中断记录 `unknown`，继续执行清理。

运行结束先清理后台任务及服务，再生成终态。切入 PLAN 持有模式切换保护直到本地 MCP 与相关副作用任务收尾。原生 payload、桥接进程与实际环境清理确认后释放代理端口，无法确认时记录未知结果。

HTTP 鉴权使用宿主环境引用或私有 credential reference。每个新请求重新检查撤销，401 保持单次发送，scope 扩展需要新的显式授权。OAuth canonical resource 与精确 transport endpoint 分别绑定，恢复连接时核对 issuer 和已记录资源，刷新保存时核对 scope、client 与 issuer。凭据文件权限、登录命令与 TUI 状态见[MCP 使用说明](mcp.md)。
