# 默认 TUI 设计

**当前开发线已接入默认 TUI，能力归 F-14。DEV-047 至 DEV-053 的 0.2.0-rc.1 候选已完成四平台原生验收，实际证据见[TUI验证](tui-validation.md)。界面细节见[TUI设计说明](tui-design.md)，正式发布安排在后续代码review与其他测试之后。**

## 默认入口

| 调用 | 当前开发线行为 |
| --- | --- |
| `saya` | stdin、stdout 均连接终端时进入 TUI |
| `saya --cwd PATH --mode code` | 使用现有全局参数进入 TUI |
| `saya chat` | 进入已有文本交互会话 |
| `saya run "TASK"` | 执行单次任务，按所选输出模式返回 |
| `saya resume ID` | 使用已有文本会话恢复入口 |
| `saya session ...`、`saya config ...` | 执行对应 CLI 子命令 |
| `saya --help`、`saya --version` | 显示帮助或版本 |
| 无子命令且无 TTY，或 stdin 来自管道 | 用法错误／2，stderr 提示显式使用 `saya run --stdin` 等入口 |
| 无子命令且选择 `--output json` 或 `jsonl` | 用法错误／2，提示选择具体 CLI 子命令 |

## 运行设置与扩展选择器

空闲界面提供以下进程内控制，运行开始后只允许查看：

- `/cd PATH`：规范化和验证目录，检查当前模式的数据目录边界，再将当前会话工作区持久迁移。相对路径以当前工作区为基准。
- `/model PROFILE`：选择已配置模型 profile，并清空当前视图建立新的空会话；裸 `/model` 列出 profile、模型与协议。
- `/effort LEVEL`、`/thinking LEVEL`：接受 `low`、`medium`、`high`、`xhigh`、`max`、`default`，更新后续请求并持久会话指纹；不修改磁盘配置文件。
- `/autocompact TOKENS|auto|off`：设置精确输入token触发水位、恢复配置百分比或关闭自动压缩；支持 `950k`、`1m` 等输入，只影响后续运行。
- `/sandbox on|off|status`：`status`可随时只读查看；`on`选择平台原生Auto后端，`off`选择Host兼容后端，切换仅允许空闲时执行并影响后续Run，权限、显式deny与PLAN边界不变。
- `/skills`、`/mcps`、`/plugins`：打开键盘选择器。↑↓或PgUp／PgDn移动，Enter选择，Esc关闭且保留聊天草稿。MCP服务Enter切换后续Run启用状态；Skill与Plugin Enter显示只读来源、状态和能力信息，不授予工具或执行权限。

命令补全可见时，Enter直接执行选中的完整无参数命令。以空格结尾的参数脚手架只填入编辑器，仍需用户提供参数。`/resume ID` 继续从TUI恢复保存会话；CLI `saya resume ID` 继续进入文本聊天恢复入口。

运行期间输入普通消息会把用户补充作为引导，排队到下一个模型边界持久化，不替换原始任务，也不取消当前模型响应或工具。审批等待时也可提交引导；当前审批仍保持待决。队列限制为16条、累计256KiB，Run结束后迟到输入被拒绝而不会静默丢失到旧Run。

`/sessions`使用弹出选择器展示会话标题、ID、模式、profile和最后状态，Enter恢复选中的会话。`/tools`将已提交工具调用按名称、状态、run／call身份、可读参数和输出结构渲染，不再直接显示完整JSON。

顶层 `Option<Command>` 已存在，实施重点为路由、TTY 判断、参数兼容和终端生命周期。位置路径简写与顶层 `--session` 属于后续易用性候选。首版通过 `--cwd` 选择工作区，通过 TUI 会话浏览器恢复。

路由和 TTY 校验先于运行准备、数据库打开及终端切换。用法错误路径的模型请求与工具调用均为零。

## 共享应用层

当前 workspace 按以下边界组织。

```text
crates/
  saya-core/   Agent 循环、协议、工具、权限、持久化
  saya-app/    模型与会话准备、运行控制、事件与应用服务
  saya-tui/    library，输入、状态、组件与终端绘制
  saya-cli/    saya 可执行入口、参数路由、文本与机器输出
```

依赖方向为 `saya-cli -> saya-app / saya-tui`、`saya-tui -> saya-app`、`saya-app -> saya-core`。`saya-core` 保持宿主界面独立，发布产物使用统一 `saya` 可执行入口。

DEV-038／039 已将模型组装、`build_runtime`、会话准备／恢复与 `events.rs` 的共享能力迁入 saya-app。会话写锁随应用会话句柄持有，UI 切换和退出由服务完成运行清理与锁释放。

## 命令、事件与背压

界面向应用服务提交发送消息、请求模式、空闲时修改权限、回复确认／澄清、取消运行、新建／恢复会话及导出等命令。服务验证 ID、运行阶段和请求版本后调用现有 core 接口。

事件包含持久业务事件、文本增量和应用状态。saya-app 提供 EventWriter／EventModel、带背压的事件 sink、确认／澄清桥和 RunCancellation，控制继续复用 core RuntimeHandle。ChannelSink 满队列投递最多等待一秒，超限返回 event_consumer_stalled，消费者关闭返回 event_consumer_closed。人工输入桥容量由调用者选择 1 至 1024，取消同时覆盖发送与回复等待。UI 侧 reducer 更新状态，渲染使用状态快照。

- 有界队列合并文本刷新，持久化序列及最终文本保留原有语义。
- 审批、错误、模式生效、最终结果等关键变化可靠传递，或通过持久水位和快照重建。
- 控制通道与绘制数据队列分开，取消和确认回复能够及时到达应用服务。
- 消费者断开后执行明确的前台运行取消及清理，保存中断结果。未来 F-08 持久任务再提供独立生命周期。

## 紧凑窗口与会话标题

当前开发线在所有窗口尺寸使用参考布局，最低支持20列×6行。黑色主区外框的顶线上显示工作目录，顶部显示实际程序版本及 Ctrl+P 命令入口。Ready／运行状态行右侧显示当前权限，灰色输入区带模式色竖线。底栏显示模式、截短的模型名称、已配置的 thinking effort 及输入用量环形指示。窄屏会缩短权限标签、状态与用量文字，详细审批仍由详情区提供。

窗口达到120列×24行时显示右侧栏，宽度取窗口的四分之一并限制在28至40列。侧栏顶部显示首条任务派生的会话名，Context区展示上下文分项条形图、估算token数和窗口占比，Tasks区显示模型维护的会话任务清单，Extensions区显示实际接入状态，下方显示profile等会话元数据和工作目录。尺寸影响信息密度与分栏，主区保持同一视觉样式。

上下文分项由共享应用层在执行模型请求边界统计，分类为System、Instructions、Skills、Preferences、Memory、Conversation、Files、Tools和Protocol。估算采用ASCII字符数除以4向上取整，加非ASCII字符数，界面标为Estimated。分项基于归一化请求组件，供应商分词和协议额外开销由实际input用量体现。尚未发起请求且没有历史计量时显示Unknown，执行请求已开始但尚未返回用量时显示`Awaiting execution usage`，独立核查不覆盖执行请求快照。恢复会话时从最近RunMetrics恢复`Last run`输入用量；`/compact`和`/cd`保留此前计量，直到下一次Execution刷新。统计通道仅传数值与固定标签，保留最新快照。

MCP和可执行插件目前显示Not implemented，Skills显示当前请求发现的元数据项数量。规划中的连接器和插件运行能力继续按后续任务推进。极小窗口中的详情优先保留可滚动内容，输入区压缩为单行草稿，PgUp／PgDn按实际可见行数翻页。

用量指示取最近一次执行模型请求的 `input_tokens`，除以执行 profile 的 `context_window_tokens`。独立安全审核和运行累计用量分别处理。每次执行请求开始时清空旧值，完成后使用服务端报告值，估算值带 `~`，缺失时显示 `—`。新建、恢复或更换 profile 后等待新的请求用量。它反映已完成请求的输入占比，当前草稿及之后的工具输出尚未计入。环形字符按占比区间显示，超出窗口时标为 `>100%`。

终端窗口标题使用 `Saya | 会话概括名`，概括名取会话首条用户任务，先进行已知凭据脱敏，合并空白后保留前80个 Unicode 字符。后续轮次沿用首条任务标题，`/new` 和 `/profile` 重置，恢复会话时重新派生。空会话为 `Saya | New session`。标题写入前移除终端控制与双向控制字符，并限制为512字节。

标题通过 OSC 2 设置，进入／退出时使用 xterm 标题栈保存／恢复。支持情况由终端或复用器决定，PTY 验收检查发送协议。重复标题不会反复写入。正常退出、错误和 panic 复用有界终端恢复路径。[xterm 控制序列](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html)

thinking effort 的配置及三协议对应关系见[配置说明](configuration.md#thinking-effort)。

## Thinking、任务清单与折叠

执行模型请求时显示Thinking状态及独立Thinking卡片，卡片标题采用精简的运行／结束／不可用状态。卡片默认折叠，点击带三角标记的标题展开或收起，Ctrl+O切换最近保留的Thinking或长工具卡片。展示内容来自服务实际返回的可读thinking／reasoning或摘要字段，服务未返回时有明确提示。静态已知凭据使用增量安全预览：完整凭据和可能在跨分片处形成的凭据前缀先替换为`[REDACTED]`，再应用显示限额；动态凭据轮换期间仍保守地等到请求结束后发布，避免已公开文本无法回收。

Chat采用 `reasoning_content`，Messages采用明文thinking块，Responses采用可读reasoning／summary字段。不透明签名、加密和redacted字段仅按协议保存回传。审核请求的推理不进入此面板。恢复会话时从对应assistant轮次的已保存明文字段重建Thinking卡片，原回答与工具结果保持各自来源。

可识别的完整结构化工具结果以摘要卡片默认折叠，标题显示工具名称、实际结果摘要、状态和调用来源。摘要包括任务完成数、文件行范围、结果项数、命令退出码及错误信息；展开后按Status、Error、Message和递归Output字段渲染参数及结构化输出，不再直接显示整段JSON。其他长工具输出超过6个逻辑行或512字节时默认折叠。标题可点击展开，同一调用的执行中与最终结果复用卡片，折叠状态绑定消息ID。显示缓存达到上限时标记截断。

全屏侧栏Tasks显示已完成数／总数及各项状态，进行中高亮。列表由运行时 `todo_write` 工具更新，恢复使用最近成功保存的快照。24至31行的侧栏优先安排任务、精简Context和Extensions，剩余任务数量有省略提示。工具协议及限额见[会话任务清单](runtime.md#会话任务清单)。

鼠标滚轮在对话区每次滚动3个视觉行，指针位于详情区时滚动详情。侧栏、编辑区和弹层不将滚轮或点击传入背景内容。TUI运行期间启用普通鼠标与SGR报告，正常退出、错误和panic通过统一guard关闭报告并恢复终端。

输入区Message标题加粗，常规空草稿显示 `Describe a task…` 渲染占位。宽度足够时，标题右侧以键帽样式提示Enter发送、Alt+Enter换行及Ctrl+O折叠。人工审批／澄清使用操作详情，粘贴超限优先显示暖色警示。底部浅收边位于留白行，极小窗口按空间简化装饰。

## 模式、权限与安全呈现

PLAN、BUILD、CODE、WORK 的选择来自用户操作。UI 同时展示当前模式与待切换请求，实际生效由 core 的调用边界和后台清理结果决定。Manual Approval 继续覆盖每次 Agent 工具调用，过期确认绑定的调用／策略版本由 core 拒绝。

界面查看已取得的运行记录和 Agent 发起工具调用具有不同事件来源。工具参数与输出进入显示前经过脱敏、大小控制及终端转义。用户输入、模型输出、文件内容和工具内容分别标记来源，控制序列作为可见数据处理。

## 技术与终端恢复

运行循环因终端错误提前退出时，仍会取消并等待运行任务，再通过运行句柄等待后台清理。运行任务 panic 或异常退出也走该清理路径，清理后再释放会话和终端。

异步会话初始化或排队任务交接失败时，原待发送内容恢复到空编辑器。编辑器已有新草稿时，保留新草稿，并将原内容作为经过脱敏的 Unsent draft 消息展示，用户可显式重新发送。

DEV-047 已锁定 Ratatui0.30.2、Crossterm0.29.0 和已有 Tokio，输入／状态更新与绘制分离。Ratatui启用Crossterm与layout-cache，Crossterm启用bracketed paste和use-dev-tty。独立输入线程使用50ms level poll，向容量64的队列发送键盘与窗口事件，异步主循环消费队列。该路径修复真实PTY缩放后首次Ctrl+D可能遗失的问题，退出前停止输入线程并恢复文件描述符。依赖与特性在Cargo.lock和crate配置中固定。[Ratatui 应用模式](https://ratatui.rs/concepts/application-patterns/)、[Crossterm 0.29 features](https://docs.rs/crate/crossterm/0.29.0/features)

终端 guard 管理 raw mode、alternate screen 和光标。正常返回、可恢复错误、panic unwind 及受处理信号走统一恢复路径，panic hook 链保留原诊断。强制终止场景记录尽力清理边界和终端恢复方法。初始化与恢复设计参考 [Ratatui panic hooks](https://ratatui.rs/recipes/apps/panic-hooks/)。

单次写入对瞬时背压最多等待100ms，单帧输出总I/O预算250ms，从同步渲染闭包完成且用户渲染代码返回后开始计时。持续背压从首次失败起最多重试恢复2秒；到期后取消所属运行并退出，空闲界面直接返回输出错误。部分帧失败后的下一次绘制先结束可能残留的OSC，清除旧画面并从空缓冲完整重绘，避免继续复用不确定的Ratatui状态。终端停止消费或连接关闭时同样进入该错误与清理路径。恢复先停止并等待输入线程，再还原termios和文件标志，屏幕控制序列最多尝试100ms。物理终端已经断开时，恢复结果取决于终端是否仍可访问。

## DEV-048 显示边界

库内流式协调器通过共享EventWriter／EventModel消费运行事件，绘制仅在状态变化时进行，目标帧间隔33ms。每轮最多主动消费64条已到达事件，键盘与取消信号优先处理。异常或输入断开后取消所属运行，关闭事件接收并等待运行收尾，再退出终端guard。

输入最多64KiB，单条正文256KiB，聊天正文总量2MiB及512条，截断与驱逐均显示标记。聊天保留最近10,000视觉行，详情最多保留2MiB／10,000逻辑行，超过显示范围有可见提示。100列起采用对话与详情双栏，窄屏详情占主区域。默认界面使用深色、英文角色标签，源文件为saya-tui的editor／view／controller模块。

### Assistant Markdown 显示

Assistant正文使用CommonMark／GFM解析，支持普通段落、ATX／Setext标题、粗体／斜体／粗斜体／删除线、行内／围栏／缩进代码、高亮、多级列表、任务列表、嵌套引用、分隔线、表格、链接、图片描述、HTML源码及脚注。Unicode数学与Mermaid按明确子集渲染，失败时整体采用源码回退。完整语法、数学／图表范围及预算见[Markdown说明](markdown-rendering.md)。

`/markdown source|render`即时切换Assistant正文的源码／排版显示，新建／恢复会话沿用本次TUI偏好。点击脚注编号可跳转定义并返回，`/footnote NUMBER`和`/footnote back`提供键盘入口。语义锚绑定消息和引用序号，窗口变化后重新计算位置。

正文统一经过控制字符净化，字符实体保留源码。渲染属于视图投影，会话存储及导出使用原始消息。有界缓存按消息、源码指纹和宽度复用已排版结果，输入、结构、单元格和总显示量超限均有可见回退或截断提示。

debug构建可运行 `saya tui-preview syntax`打开共享场景的交互预览，←／→切换、s／r选择source／render、q退出。现有 `render_preview`继续提供离线文本和单元格JSON快照，场景和命令示例见[预览入口](markdown-rendering.md#debug-预览)。

## DEV-049 运行控制

Ctrl+P打开居中的浮层命令面板，方向键选择、Enter执行选中项，Esc或再次Ctrl+P关闭。/mode plan|build|code|work由用户触发，标题同时显示实际模式和core待切换模式。/permissions auto|manual|bypass在运行空闲时修改本次权限设置。/status、/cancel、/help与/exit提供运行状态和控制。

当前模式具有专属色，WORK为晴蓝 `#58A6FF`，CODE为薄荷绿 `#7DCB9B`，PLAN为薰衣草紫 `#BB9AF7`，BUILD为暖杏橙 `#F6AD55`。输入框色条与底栏实际模式文字同步着色。待切换时，底栏当前与目标文字各用其模式色，色条随实际生效模式更新。

输入框为空且命令面板关闭时，Tab按WORK→CODE→PLAN→BUILD→WORK循环模式。运行中显示待生效模式，连续按下从最近请求的选择继续循环，进入PLAN仍遵循后台清理和调用边界。切换会使旧审批失效。含空格、正文或命令前缀的草稿沿原编辑／补全处理，权限设置独立。

### 弹出命令面板

命令面板覆盖在当前界面上，使用圆角边框、选中高亮、命令说明和选择计数。宽度最多88列并保留两侧空间，高度最多14行，窗口缩放后保持选中项可见。列表使用与帮助／补全相同的28项命令目录，滚动窗口随选择移动，在可见范围内选择时保持行位置。

↑／↓或候选行上的鼠标滚轮选择命令，鼠标点击只更新选择，Enter执行高亮项。Esc或再次Ctrl+P关闭后回到当前详情、滚动位置及草稿。弹层打开时，普通字符、Tab和粘贴由命令面板接管，输入光标与斜杠建议按浮层状态呈现。背景的工具折叠和滚动等待面板关闭后操作。

选择带参数前缀会填入空草稿，已有草稿时提示先处理该内容。Enter读取当前高亮命令，原有斜杠草稿保留在编辑器中。提交与关闭要求新的按键Press，重复事件经过边界验证。Ctrl+C执行取消，空草稿Ctrl+D沿终端退出与清理规则处理。

待审批或澄清内容随真实请求更新。若异步详情遮盖了当前请求，下一次回复先恢复请求详情，再次按Enter才提交回复。20×6窗口保留三项候选、选中标记、导航与Esc关闭提示，两侧边缘留白。

### 输入、恢复与渲染边界

运行前的可恢复校验错误在界面显示提示并保留草稿，存储错误和未持久化副作用按致命错误收尾。取消UI查询保留编辑内容，取消首条消息的异步会话准备会恢复未发送任务。显式 `/resume` 使用目标会话保存的工作区、模式及profile，后续会话操作按当前界面命令处理。

粘贴中的CR／CRLF统一为LF。标题经过空白和控制字符归一化后再执行凭据检查。单个显示grapheme最多128字节，视觉行最多4 KiB，超限以省略号呈现，消息与草稿原文保留用于后续正常处理。退出信号触发收尾后等待所拥有任务结束，终端恢复由生命周期管理完成。

### 斜杠命令补全

当前开发线在输入框首字符为 `/`、单行且光标位于末尾时显示前缀匹配建议。候选目录共24项，包含工作模式、权限、会话与工具入口，以及导出格式和需要用户补齐参数的命令前缀。命令面板、帮助和补全共用[命令目录](../crates/saya-tui/src/commands.rs)。

↑／↓循环选择候选，Tab或末尾→将候选写入输入框，Enter执行输入框中的命令。灰色后缀表示建议文本，接受后才成为草稿。Esc隐藏建议并保留输入，Tab可以重新接受该前缀的建议，输入变化时重新筛选。无匹配的命令前缀按Tab保留原文。`//`字面量斜杠、多行和光标位于中间时使用常规编辑。

候选弹层位于输入框上方，最多显示6项、选中标记和命令说明。空间不足时保留灰色后缀与底栏提示，输入框和光标获得显示空间。待人工审批时，第一次Esc或Shift+Esc关闭建议，后续Esc沿审批交互处理。

`/profile `、`/resume `、`/resume-accept `、`/cancel-job `和导出格式补全保留末尾空格，profile名、会话／任务ID及目标路径由用户填写。命令面板选择这些前缀时填入空草稿，有普通消息草稿时提示先处理草稿。缺少导出路径会同步提示补齐并保留输入。

逐工具审核显示tool、call_id、approval_id、工作区、模式及参数，y批准、n或Esc拒绝。决策要求当前审核可见，并使用新的普通／Shift按键，重复和Ctrl／Alt／Super组合键保持编辑语义。澄清在输入框填写后Enter回复，//转义支持字面量斜杠。待审核时仍可输入/mode切换，旧reply立即失效，实际授权由core在派发前重查。人工等待的活跃预算计时沿用core pause逻辑。

## DEV-050 会话与记录入口

`/new` 创建会话并等待输入，`/sessions [PAGE]` 每页列出20条记录，`/resume ID` 恢复历史、原模式与配置引用。配置变化需使用显式 `/resume-accept ID` 接受。恢复使用本次启动的权限设置，等待新输入。`/profiles` 查看配置中的模型，`/profile NAME` 在空闲时选择并释放原会话，下一条消息创建新会话。

`/tools` 和 `/jobs` 读取当前会话的一致性快照，展示持久化水位、run_id 和 call_id，保留 unknown、错误与截断状态。面板标记 UI 查询来源，沿用现有记录读取服务。`/cancel-job ID` 向当前运行请求取消所属后台任务。

`/export json|markdown PATH` 导出对话，`/export-full json|markdown PATH` 显式包含完整范围及工具记录。路径支持空格，相对路径基于当前工作区。导出复用安全文件发布、已有文件保护和 PLAN 路径检查，回执带持久化水位。已完成发布的文件即使随后取消，界面仍报告实际回执。

会话初始化、恢复和快照／导出通过独立 UI 任务执行。Ctrl+C 可请求取消，退出时等待任务收尾。UI 任务结束后才能应用排队的模式变化，权限修改要求运行与 UI 任务均空闲。读取到的正文沿用脱敏与有限显示缓存。
