# 提示词缓存 95% 与工具错误联合验证

**日期：2026-11-11**

**状态：本机 DeepSeek 实测达到整体缓存命中率95%以上，并在相同样本规模下减少失败工具调用。结果不构成 provider 缓存保证，也不代表其他模型或服务。**

**后续10场景模型任务能力验证见[提示词与模型任务能力联合验证](prompt-capability-2026-11-11.md)；本文件保留前一阶段证据。**

## 目标与验收口径

本轮在[前一轮多轮缓存报告](prompt-evaluation-2026-11-11.md)的83.54%整体命中率上继续改进，目标为：

- 合并真实运行的整体缓存命中率达到或超过95%，不排除首轮或冷启动运行。
- 保持场景验收通过，并减少失败工具调用；不同运行数量同时比较绝对数、错误运行率和每次模型请求错误率。
- 不把模型连接失败、任务失败或无效工具调用从报告中删除。

所有组使用同一 `deepseek-flash`、Chat Completions 兼容协议、128000窗口、8192输出上限及8个既有场景。每次运行使用独立临时工作区和HOME，显式拒绝 `exec`。最终候选每批为8场景×6次重复，共48次；两批合计96次。

## 最终实现

1. **共享系统与工具前缀**：动态系统段只保留相同有效配置下稳定的宿主、profile、模型、协议、模式和权限事实。
2. **实例数据后移**：精确运行时间与工作区放入 `saya_runtime_context_v1`；执行环境实例ID、策略摘要和能力放入紧随其后的历史数据项。这些字段仍提供给模型，但位于工具schema之后，不再阻止不同工作区复用系统与工具前缀。
3. **运行内稳定**：同一Runtime的后续模型轮次复用同一时间快照；时间与实例数据不作为持久历史保存。
4. **有界搜索指导**：查找匹配文本或特定条目时先 `search_text`，即使不知道文件大小也不用 `read_file` 从第1行扫描；搜索命中已满足提取时直接使用结果。
5. **补丁计数与上下文**：明确单行替换时 `old_count = new_count = hunk_body_lines - 1`，上下文必须连续且不能跳过中间行。
6. **Skill生命周期**：要求成功激活后再读取资源；`skill_inactive` 表示先激活而不是重复读取。
7. **逐项交付**：WORK要求逐项保留每个字面来源标签和值，只有总数或无标签列表不算满足。

## 工具错误比较

前一轮48次运行有4次失败工具结果，涉及4次运行、212次成功模型请求。最终96次运行有6次失败工具结果，涉及6次运行、397次成功模型请求：

| 口径 | 前一轮 | 最终合并 | 变化 |
| --- | ---: | ---: | ---: |
| 每48次运行的失败工具结果 | 4 | 两批均为3 | 同规模下降25% |
| 含工具错误的运行比例 | 4/48 = 8.33% | 6/96 = 6.25% | 下降2.08个百分点 |
| 每次成功模型请求对应的失败工具结果 | 4/212 = 1.89% | 6/397 = 1.51% | 下降约19.9% |

合并样本的绝对错误数为6，高于旧样本的4，因为运行数翻倍；不能据此声称绝对数也下降。最终两批各自均为48次、3次错误，且96次任务验收全部通过。

剩余错误为4次 `invalid_patch`、1次 `patch_conflict` 和1次 `skill_inactive`，全部在后续修正后通过。本轮减少但未消除这些模型调用错误。
