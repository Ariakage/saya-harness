| 来源中的设计或措辞 | Saya 的采用方式 |

| 全量摘要保留用户目标、重要技术细节、错误修复、当前工作和待办 | 保留这些事实维度，增加验收条件、证据级别、来源引用和用户更正 |
| 输出 `<analysis>` 与 `<summary>`，再抽出摘要 | 输出一个符合宿主schema的JSON对象，集中保存可复核的最终事实与不确定项 |
| 逐条列出所有用户消息及大量完整代码 | 优先保存当前有效要求、原始来源ID和必要短引文，大正文使用文件及输出引用 |
| 来源材料可添加 `Compact Instructions` | 摘要任务由宿主协调器指定，项目文件、工具结果与引文保留各自来源和作用域 |
| 续接段用一句说明和摘要插值恢复对话 | 续接明确区分历史摘要、保留后缀和本次有效运行状态，接回完整目标与剩余工作 |

## 接入契约

摘要请求使用独立角色和空工具集合，工具调用、次数、活跃时间及输出长度由运行时约束。输入由协调器选择可压缩的完整协议组，包含来源角色／ID、压缩水位、原始必留约束、引用与明确的输出schema。只有可展示内容进入摘要输入，供应商opaque／signature状态由适配器保留。

摘要验证在宿主完成，覆盖schema、已知来源、必留约束、引用归属、当前记忆版本／遗忘、剩余输入预算及来源水位。模型生成的摘要保持任务上下文的证据级别，历史批准携带原始范围和来源。实际工具调用仍经过本次运行的模式、权限、路径与预算检查。

检查点与ContextView指针通过来源水位CAS原子提交。条件式续接规则固定于静态前缀，动态checkpoint_selected_by_host标志控制本次适用性，所有字节参加预算。恢复重新读取本次配置、有效模式与权限、当前项目／Skill来源、记忆版本和可用工具。压缩失败与保存冲突保留原始会话和此前有效检查点。[上下文设计](../../../context-management.md)

DEV-063使用版本1结构化schema，包含来源范围、objective、constraints、decisions、completed、remaining、uncertainties、required_ids和references。事实保留source IDs、evidence等级与状态。协调器复用实际请求计数，默认80%触发、严格55%目标，单用户长Run保留最新原文重放。记忆失效组先由宿主来源证明替换，再映射到摘要输入。原始草案继续保留学习轨迹，当前版本和提示词指纹沿运行时记录维护。

### Saya来源角色与输出预算

2026-11-10的真实模型探索中，Responses摘要被宿主以 `Summary evidence level differs from its source role`拒绝。该结果暴露了参考提示词的通用来源描述与Saya实际source_units角色之间的指引缺口。运行时Compact现明确列出user、assistant／assistant_partial／assistant_tool_call、tool_observation、provider_state、retired_group和prior_summary_data的对应关系。助手的完成汇报保留claim／inference，工具请求保留意图身份，observed引用实际工具观察或供应商元数据，user_request只引用原始用户，退休内容继续禁止引用。

预算指引增加空数组、简短事实与紧凑JSON，先保全必需事实、每个原始用户来源和精确引用ID，允许同一必需事实同时满足用户来源覆盖，减少分类之间的重复。schema、来源角色、必需项逐字保全、引用完整性与55%投影目标保持当前运行时校验。该段记录提示词修正，真实模型复验与最终候选状态继续由N3验收记录维护。

## 验证要求

- 检查英文正文、稳定前缀、来源清单与实际装配段的对应关系。
- 三协议测试完整工具组及适用的opaque／signature后缀保真。
- 用可控摘要夹具验证用户更正、来源伪造、摘要注入、失效引用、未知副作用、重复压缩和约束遗漏。
- 验证摘要调用计入请求／token／时间预算，取消、并发revision变化及存储失败保持可恢复状态。
- 验证续接使用本次权限与记忆版本，完整目标和验收要求继续保留。
- 真实模型质量单独记录执行模型、profile、提示词指纹、来源范围、实际输出和失败结果。
