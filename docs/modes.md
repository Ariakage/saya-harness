# 工作模式

**状态：已定案；模式控制与英文提示词已接入可复用 core 循环并通过受控验证；真实协议和 CLI 尚未接入。**

## 已确认的产品定义

Saya 同时支持编程任务与通用任务，并提供四个可切换的工作模式。新会话默认 WORK；恢复会话时恢复原工作模式。

工作模式与 `auto`、`bypass permissions`、`Manual Approval` 三种权限模式分别配置，权限规则见[执行与恢复契约](execution.md)。

| 模式 | 已确认的职责 | 完成标准 |
| --- | --- | --- |
| PLAN | 只读调查、需求分析与规划，输出计划，不修改工作区文件 | 目标理解、澄清、步骤与验收方法；只用只读文件／搜索与人工交互 |
| BUILD | 端到端实现和交付 | 必要实现、适用验证、产物与说明；未完成项明确披露 |
| CODE | 聚焦代码编写、修改与调试 | 聚焦改动与相称验证，可测试和审查相关改动 |
| WORK | 通用任务执行 | 完成本地通用任务并交付结果或文件，说明依据与未完成项 |

BUILD 的职责包含端到端实现和交付，不能将其缩减为执行构建命令。CODE 包含与任务相关的测试和审查。所有模式都可直接回答、使用允许的工具或发起澄清，不强制先进入 PLAN。

“模式”与“编程／通用任务”是两个不同维度；按当前职责选择模式，不要求每个模式单独实现一套任务引擎。具体交付见完整基线 B-07。

## 职责与执行策略

执行规则已确定：

- PLAN 输出计划文字；工作区内的计划文档同样属于文件，不在 PLAN 下修改。通用 exec 被禁用，不依据命令名称猜测只读。
- WORK 首先通过本地文件与命令工具完成通用任务，按目标交付文件或结果；网络、浏览器与外部工具不进入 0.1。

PLAN 的会话保存、日志与缓存保持目标工作区不变，存储在基线 B-18 的工作区外 XDG 目录；重叠时启动检查失败，不默默写入工作区。

PLAN 的只读要求在三种权限模式下均由工具执行边界落实。BUILD、CODE、WORK 按权限模式处理；路径、核查、确认与预授权遵循完整基线 B-09 至 B-11。

## 选择与切换

由用户手动切换工作模式，Agent 可以建议但不自行切换。运行中记录请求，当前调用完成后、下一次调用前生效，同一会话保留上下文。CLI 使用 `--mode plan|build|code|work`，REPL 使用 `/mode`，语法与输入规则见完整基线 B-03。

切换行为如下：

| 项目 | 已确定行为 |
| --- | --- |
| 初始模式 | 新会话默认 WORK；恢复沿用原工作模式，显式用户参数可覆盖 |
| 切换时机 | 运行中记录请求，当前调用完成后、下一次调用前生效 |
| 切换来源 | 用户手动切换，Agent 可建议，不自行切换 |
| 上下文 | 同一会话保留完整协议上下文；0.1 不自动摘要或迁移协议／模型 |
| 执行中的工作 | 前台调用按边界完成；切入 PLAN 前取消并清理后台写入和命令，未执行工具重新校验；连续请求最后一次优先 |
| 等待确认 | 可立即应用切换，使旧确认失效并重新判断 |
| 取消 | 取消优先，清理当前调用，最后请求的工作模式留给下一次输入 |
| 执行策略 | PLAN 始终只读，其他操作按权限模式处理；权限只能在空闲时修改 |

保留上下文不意味着继续沿用旧模式的执行权限。

## 架构与验证

四模式英文提示词、权限说明、实际装配和来源取舍见[提示词定制](prompts.md)；提示词引导不替代工具执行边界。

由运行时管理模式行为，界面展示当前与待切换模式并传递用户选择；未来 TUI、GUI 复用相同定义。具体设计见[架构设计](architecture.md)。

实现后验证用户所选模式与实际模式一致，覆盖切换、上下文、等待确认及进行中的工作。模式切换本身不作为任务完成证据。

相关确认见[决策记录](decisions.md) D-027 与[完整基线](mvp-baseline.md) B-07 至 B-11；早期方向由 D-004 至 D-026 追踪。
