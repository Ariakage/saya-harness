## 1. 执行摘要与总体结论

Saya Harness 当前代码库展现了很高的 Rust 系统工程水准：

## 3. 代码与运行时审查发现（按风险等级分级）

### 3.1 P1 高优先级发现

#### R2-01：`redaction::redact` 与 `contains_secret` 能力不对称，非纯 JSON 文本中的 Unicode 转义凭据漏脱敏并引发存储与事件层状态撕裂

- **定位**：
  - [`crates/saya-core/src/redaction.rs`](../crates/saya-core/src/redaction.rs) 第 `74-95` 行（`variants`）、第 `105-159` 行（`decode_text_escapes` / `contains_secret`）、第 `199-241` 行（`redact_string`）、第 `274-290` 行（`redact` / `tool_result`）
  - 受影响下游调用点：[`crates/saya-cli/src/main.rs`](../crates/saya-cli/src/main.rs) 第 `569-575` 行（`redacted_text`）、[`crates/saya-app/src/thinking.rs`](../crates/saya-app/src/thinking.rs) 第 `184-194` 行（`Capture::publish`）、[`crates/saya-tui/src/controller.rs`](../crates/saya-tui/src/controller.rs) 第 `115-124` 行（`App::safe`）、[`crates/saya-core/src/dispatch.rs`](../crates/saya-core/src/dispatch.rs) 第 `396, 436, 495` 行、[`crates/saya-core/src/sqlite.rs`](../crates/saya-core/src/sqlite.rs) 第 `423-443` 行、[`crates/saya-core/src/logging.rs`](../crates/saya-core/src/logging.rs) 第 `143, 225` 行、[`crates/saya-core/src/export.rs`](../crates/saya-core/src/export.rs) 第 `302` 行、[`crates/saya-app/src/events.rs`](../crates/saya-app/src/events.rs) 第 `125-131` 行。
- **根因分析**：
  - 提交 `bce1f90` 为检测函数 `contains_secret` 增加了 `decode_text_escapes`，可识别普通散文、Markdown 代码围栏或多行 JSONL 中的 `\uXXXX`、UTF-16 代理对与 `\/` 编码凭据。
  - 但负责执行脱敏的 `redact_string`（第 `210` 行）仅当**整段字符串本身是单个合法 JSON 值**（`serde_json::from_str::<de::IgnoredAny>(text).is_ok()`）时才会解码内部转义；一旦文本是自然语言、Markdown 或多行 NDJSON（例如 `"key = sk-\u0073ecret"`），`nested` 为 `None`。随后 `variants()` 仅构造 `serde_json::to_string` 的最小转义（不会把普通 ASCII 字母转为 `\u00XX`），末尾第 `280` 行又仅调用 `contains_raw(&serialized, secrets)` 而非 `contains_secret`，导致 `redact()` 与 `tool_result()` 返回 `Ok(())` 且原样保留编码凭据。
- **实际影响**：
  1. **多通道泄露**：所有只调用 `redact` 而未额外调用 `contains_secret` 的路径——包括 `saya run` 默认 `--output text`、`saya chat`、`/dev/tty` 审批／澄清提示、`ThinkingModel` 实时快照、TUI `App::safe`、`SqliteStore` 落盘、`saya.log` 结构化日志、`session export` 导出文件以及无 `EventWriter` 包装时的工具结果回传——均会放行正文中内嵌的 `\uXXXX` 已知凭据。
  2. **落盘后事件层崩溃撕裂**：在 TUI 或 `--output jsonl` 下，含 `\uXXXX` 凭据的工具结果先通过 `SqliteStore::commit` 写入数据库，随后在 `EventWriter::event`（`events.rs:126`）被 `contains_encoded_secret` 拦截并以 `output_error` 炸断整轮运行，造成“敏感结果已入库，但运行非预期崩溃”的不一致状态。
- **修复建议**：在 `redaction::redact`（第 `280` 行）或 `redact_string` 末尾统一接入与 `contains_secret` 同源的转义感知复核；若字面替换与嵌套 JSON 脱敏后仍可解码出已知凭据，直接返回 `Err(failure())` 触发 fail-closed 扣留，使存储、工具分发、日志、导出、CLI 与 TUI 行为完全一致。

#### R2-02：`exec` 预授权（`--approval-file`）与显式 `allow` 规则忽略模型注入的 `args.env` 覆盖变量

- **定位**：
  - [`crates/saya-core/src/tools/exec.rs`](../crates/saya-core/src/tools/exec.rs) 第 `249-280` 行
  - [`crates/saya-core/src/permissions.rs`](../crates/saya-core/src/permissions.rs) 第 `200-218, 426-470` 行
  - [`crates/saya-core/src/approvals.rs`](../crates/saya-core/src/approvals.rs) 第 `473-510` 行
- **根因与触发路径**：
  1. `ExecTool::prepare` 允许模型通过 `args.env` 注入任意不在 `secret_env_names` 中的 `EnvValue::Literal` 变量（如 `DYLD_INSERT_LIBRARIES`、`LD_PRELOAD`、`GIT_SSH_COMMAND`、`GIT_CONFIG_COUNT`/`GIT_CONFIG_KEY_0`/`GIT_CONFIG_VALUE_0`、`RUSTC_WRAPPER`、`PYTHONPATH`、`NODE_OPTIONS`、`HOME` 等）。
  2. `Operation::command_identity()`（`permissions.rs:200-218`）仅返回 `(argv, cwd)`，丢弃了 `environment_digest` 与自定义 `env`。当命令进入 `Decision::Ask` 时——包括 `Manual Approval`，**甚至在 `auto` 模式下独立安全核查模型（`review.rs`）已识别出恶意 `env` 并明确返回 `"ask"` 时**——`approvals.rs:483-490` 仅比对 `item.argv == argv && item.cwd == cwd`，会静默消耗 `--approval-file` 中干净命令的预授权并直接签发携带恶意 `env` 的 `OneShotPermit`。
  3. 同理，用户在 `[permissions.rules]` 配置的显式 `allow` 规则（如放行 `/usr/bin/git status`）在 `Rule::matches` 中不检查 `args.env` 是否为空，会直接返回 `Decision::Allow` 跳过 `ModelReview`。
- **修复建议**：
  - 预授权默认仅匹配基准继承环境（即要求 `args.env.is_empty()` 或 `environment_digest` 与空覆盖基准环境一致），除非未来 schema 显式声明允许的环境变量；
  - 静态 `allow` 规则在未显式声明环境策略时，若 `args.env` 非空应降级为 `ModelReview`（`auto`）或 `Ask`（`Manual`）；同时建议在 `exec.rs` 内置高危动态链接器注入变量（如 `LD_PRELOAD`、`DYLD_*`）硬拦截黑名单。

#### R2-03：`Policy::new` 未规范化 `path_glob` 的静态目录前缀，在 macOS 符号链接路径或软链工作区下导致显式 `deny`/`ask` 规则静默失效

- **定位**：[`crates/saya-core/src/permissions.rs`](../crates/saya-core/src/permissions.rs) 第 `120-135, 245-271, 281-298, 331-346, 387-399` 行。
- **根因与影响**：
  - `Policy::new` 对 `workspace`、`additional_roots` 与 `rule.executable` 均执行了 `std::fs::canonicalize`，`Operation::file` 与 `Operation::exec` 也会将目标路径规范化为真实物理路径（例如在 macOS 上 `/tmp/...`、`/var/...`、`/etc/...` 会变为 `/private/tmp/...`、`/private/var/...`、`/private/etc/...`）。
  - 唯独 `rule.path_glob`（第 `335-344` 行）直接将原始配置字符串送入 `GlobBuilder::new(pattern)`，未对其不含通配符的已存在父目录前缀做 `canonicalize`。
  - 当用户在 macOS 临时目录或通过符号链接访问的工作区配置 `effect = "deny", path_glob = "/tmp/repo/.env*"` 时，运行期目标 `"/private/tmp/repo/.env"` 无法命中该 glob，导致显式 `deny`/`ask` 规则被静默旁路（包括在 `bypass permissions` 模式下违反 [B-06](mvp-baseline.md)“显式 `deny` 规则仍然生效”的不变量）。
- **修复建议**：在 `Policy::new` 编译 `path_glob` 前，提取首个通配元字符（`*`、`?`、`[`、`{`）之前的静态路径前缀，若前缀或其已存在祖先目录包含符号链接则规范化后再拼接剩余 glob 模式（或同时保存原始与规范化双 matcher 任一命中即生效），并拒绝含 `..` 组件的 `path_glob`。

#### R2-04：`saya chat` / `saya resume` 异常退出漏调后台清理并提前释放会话锁，且 `saya run` / `saya chat` 未捕获 `SIGTERM` / `SIGHUP`

- **定位**：
  - [`crates/saya-cli/src/chat.rs`](../crates/saya-cli/src/chat.rs) 第 `198-206, 304, 321-606` 行（重点第 `331, 355-358, 373, 403, 472-602` 行）
  - [`crates/saya-cli/src/main.rs`](../crates/saya-cli/src/main.rs) 第 `732-740` 行
  - 对照实现：[`crates/saya-tui/src/controller.rs`](../crates/saya-tui/src/controller.rs) 第 `68-72, 337-352, 412-427, 685-687, 693-695` 行与 [`crates/saya-core/src/tools/exec.rs`](../crates/saya-core/src/tools/exec.rs) 第 `470` 行。
- **根因与影响**：
  1. **早退脱离运行任务并提前解锁**：在 `saya-tui` 中（R-05 修复后），外层通过 `app.shutdown().await` 保证任何终端 I/O 或内部错误都会先 `cancel()`、等待 `active.join` 并执行 `active.handle.shutdown_background().await`，随后才释放 `Prepared._lock`（`SessionLock`）。但在文本交互入口 `chat.rs` 中，`Active` 无 `Drop` 取消，事件循环内大量操作（如流式输出 `console.print(&delta)?`、`/jobs` 查询等）直接使用 `?` 返回：一旦 `stdout` 管道断开或控制台写入报错，`JoinHandle` 被直接丢弃（在 Tokio 中丢弃 `JoinHandle` 不会中止任务而是将其后台分离），而局部变量 `prepared` 立即析构释放排他文件锁 `SessionLock`，造成后台 `runtime.run` 与子进程在无锁状态下继续写库和修改工作区。
  2. **`JoinError` 分支漏调 `shutdown_background()`**：`chat.rs:355-358` 在 `run.join` 返回 `Err(_)` 时直接 `return Ok(1)`，未调用 `old.cancel.cancel()` 与 `old.handle.shutdown_background().await`。
  3. **缺少 `SIGTERM` / `SIGHUP` 信号捕获**：`exec.rs:470` 将每个命令放入独立进程组 `process_group(0)`。`saya-tui` 监听了 `SIGINT`、`SIGTERM`、`SIGHUP`，而 `saya run` 与 `saya chat` 仅监听 `SIGINT`。当 CI、容器编排器、`timeout` 或 SSH 断连向 `saya run`/`saya chat` 发送 `SIGTERM` 或 `SIGHUP` 时，`saya` 立即按系统默认信号行为终止，独立进程组中的工具子进程不会收到信号而沦为孤儿进程，且 SQLite 中的运行记录保持未关闭状态。
- **修复建议**：将 `chat.rs` 主循环封装到内部函数，外层统一执行与 `saya-tui` 相同的 `cancel -> join -> shutdown_background` 收尾后再释放 `prepared`；在 `saya run`、`saya chat` 与 `saya session export` 中统一补齐 `SIGTERM` 与 `SIGHUP` 优雅取消处理。

#### R2-05：`saya session list` 与 `saya session show` 在默认 `--output text` 模式下未清洗 C1 控制序列与 Bidi 欺骗字符

- **定位**：[`crates/saya-cli/src/main.rs`](../crates/saya-cli/src/main.rs) 第 `910-914` 行（`query_sessions`）。
- **根因与影响**：
  - 会话历史按契约原样保存模型与工具返回的原始文本；R-01 的回归测试（`crates/saya-cli/tests/cli.rs:1053-1061`）仅校验了 `--output json`。
  - 在默认的 `--output text` 分支，`query_sessions` 直接执行 `println!("{}", serde_json::to_string_pretty(&data)?)`。`serde_json` 只转义 `U+0000..=U+001F`，**不会转义** `DEL`（`U+007F`）、8-bit C1 控制字符 `U+0080..=U+009F`（含 `CSI = U+009B`、`OSC = U+009D`）以及 Unicode Bidi 覆盖符（如 `U+202E` RLO）。当历史消息含上述字符时，终端排障执行 `saya session show <id>` 会直接向终端注入原始控制序列或触发视觉反转欺骗。
- **修复建议**：在 `query_sessions` 的 `Output::Text` 分支对输出字符串执行控制符与完整 Bidi 字符转义（保持 `Output::Json` 结构化契约不变），并补充 `--output text` 回归测试。

  3. **`Diagnostics::drop` 排空顺序与日志目录 TOCTOU**：当低优 `normal` 队列满且磁盘慢时，`Drop` 先调用 `self.flush(EXIT_WAIT)` 自旋耗尽全部 2 秒预算，随后才设置 `closed = true` 并以 `0ms` 超时放弃 `worker.join()`，导致高优 `priority` 通道内的 `WARN`/`ERROR` 来不及落盘；此外 `logging::open_root` 缺少查询侧 `query.rs:112-131` 具备的打开后 `dir_metadata()` 身份复核。
  4. **`session export` 路径基准**：CLI 将相对 `--file` 解析到 `current_dir()` 而 TUI 解析到 `config.cwd`；且在工作区外以 `--mode plan` 导出某历史会话时，`publish()` 仅检查当前 `config.cwd` 而未同时保护 `snapshot.session.workspace`。

## 5. 后续设计草案（N2–N5）前瞻性技术审查

仓库将尚未实现的能力清晰标注为设计草案（[`sandbox.md`](sandbox.md)、[`context-management.md`](context-management.md)、[`saya-plugin.md`](saya-plugin.md)、[`browser.md`](browser.md)、[`memory.md`](memory.md)、[`goal.md`](goal.md)），并未提前混入 MVP 代码，符合 [`AGENTS.md`](../AGENTS.md) 边界要求。在未来进入 N2–N5 实施前，建议提前关注以下架构与安全耦合点：

1. **原生隔离（[`docs/sandbox.md`](sandbox.md)，N2）**：
   - **macOS Seatbelt 演进风险**：Apple 已将 `sandbox_init` / `sandbox-exec` 标记为废弃接口，后续 macOS 大版本存在移除或收紧风险。D-040 将其封装在独立 `SeatbeltBackend` 后面的方向非常正确，建议在 `SandboxBackend` trait 设计时避免泄露 SBPL 专属语义，确保未来可平滑切换至 Virtualization / 容器后端。
   - **Linux 非特权 User Namespace 限制**：Ubuntu 24.04+ 默认开启 `kernel.apparmor_restrict_unprivileged_userns=1`，可能导致无 AppArmor profile 的 `bwrap` 启动即失败。建议在 `BubblewrapBackend` 预检阶段给出可诊断错误并严格映射至已预留的退出码 `5`（不静默降级为无沙箱运行）。
   - **`socat` 代理桥接边界**：通过 Unix Socket 桥接出站域名白名单时，需由宿主机受控 HTTP CONNECT / TLS SNI 代理执行域名校验，不能仅允许任意 TCP 转发，并防止子进程通过自定义 DNS 或 IP 直连绕过域名策略。
2. **上下文管理与 Compact（[`docs/context-management.md`](context-management.md)，N2）**：
   - **原生协议历史配对不变量**：当前 `saya-app/src/context.rs:237`、`provider/anthropic.rs:455-471` 与 `provider/responses.rs` 均严格依赖 `[HistoryItem::ProviderItem, HistoryItem::AssistantText/ToolCall]` 的**紧邻配对**以及 `ToolCall` ↔ `ToolResult` 的完整闭合（Anthropic 还校验 `thinking` 签名块与紧随其后的 `tool_use` 归属同一条 assistant 消息）。实施 Compact 裁剪或摘要归档时，必须以“整轮完整模型响应 + 对应全部 `ToolResult`”为最小不可分割原子单元，否则裁剪后会直接触发 `invalid_history` 或上游 API 400 错误。
3. **跨会话记忆（[`docs/memory.md`](memory.md)，N3）**：
   - **`PLAN` 零副作用与跨仓库污染边界**：草案提出默认加载并允许模型更新 `~/.saya/MEMORY.md`。实施时需明确两点硬约束：① `PLAN` 模式下必须禁止模型自动修改 `~/.saya/MEMORY.md`（保持只读调查契约）；② 写入与读取 `~/.saya/MEMORY.md` 必须经过当前与全局凭据脱敏检查，且始终置于不可信 `UserText` 数据信封内，防止恶意仓库通过提示词注入把持久化指令写入全局 `MEMORY.md` 污染其他项目会话。
4. **插件与 MCP 规范（[`docs/saya-plugin.md`](saya-plugin.md) & [`saya-plugin-v1.schema.json`](schemas/saya-plugin-v1.schema.json)，N3/N4）**：
   - **MCP 凭据纳入统一脱敏集合**：插件清单通过环境变量引用向 MCP Server 注入凭据时，必须将这些环境变量名并入 `Config::secret_env_names()`，否则 MCP 工具输出回显的插件密钥无法被 `redaction` 与流式缓冲机制自动拦截。
   - **JSON Schema 与 TOML 映射一致性**：`saya-plugin-v1.schema.json` 顶层使用 `additionalProperties: false`，实施 `saya plugin validate` 时需确保 TOML 表结构转换到 JSON 后的类型（尤其是整数／时间戳／路径相对锚点）与 `cap-std` 插件根目录隔离完全对齐。
5. **Browser 自动化（[`docs/browser.md`](browser.md)，N4）与自主 Goal（[`docs/goal.md`](goal.md)，N5）**：
   - **Browser 调试端口隔离**：启动受控 Chromium 时应优先使用 `--remote-debugging-pipe` 或带随机鉴权路径的 `127.0.0.1:0` 临时端口，避免固定本地端口被同一宿主机的其他非授信进程或 `exec` 工具连接窃取会话 Cookie；网页 DOM / 控制台文本进入上下文前须按完全不可信外部数据做长度截断与凭据扫描。
   - **Goal 跨 Run 累积预算与人工门禁**：`Goal` 在多轮 `Run` 之间自动推进时，除单次 `RuntimeLimits` 外还需强制执行 Goal 级总墙钟时间、总模型请求数与总 Token／费用硬上限；一旦任意子 Run 返回 `NeedsConfirmation`、`NeedsInput` 或存在 `outcome_unknown` 副作用记录，必须立即挂起交由人工裁决，绝不自动重试未知副作用操作。
