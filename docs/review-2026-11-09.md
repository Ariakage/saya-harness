## 确认问题与修复

### R-01 P1 文本流允许终端控制序列注入

- 位置为 [main.rs](../crates/saya-cli/src/main.rs) 的 `PrintStream::next` 和 `safe_terminal_text`。
- 未配置已知凭据、启用流式文本输出时，模型增量直接进入 stdout。基线 release 程序的本地 SSE 夹具确认，跨片段 OSC 52 和 BEL 原样到达 stdout，支持该序列的终端可据此修改剪贴板。完整回答和其他文本路径还保留双向文本控制符，可造成视觉顺序伪装。
- 修复 `d32c48b` 复用已有终端清洗入口，流式与完整文本均替换控制符，保留正常 Unicode、换行和 Tab。JSON／JSONL 和持久历史继续保留原始语义。
- 回归 `text_output_neutralizes_controls_without_changing_machine_output_or_history` 通过实际 CLI 验证两种流设置、三种输出及历史读取。基线复现位于 `target/review-20261109/terminal-osc-before.json`。

### R-02 P1 个人上下文的编码凭据可发送给模型

- 位置为 [main.rs](../crates/saya-cli/src/main.rs) 的 `personal_context`。
- `--memory-file` 和 `--preferences-file` 只用明文子串拒绝已配置凭据，带引号或反斜杠的 JSON 编码凭据及 Unicode 转义可绕过，内容进入执行请求。多个 profile 的凭据都属于检查范围，因此可能将其他服务的凭据发送到当前模型服务。
- 修复 `d32c48b` 改用现有共享编码凭据检测。歧义或无法安全检查的内容继续失败关闭，错误不回显文件正文。
- 回归 `encoded_credentials_in_personal_files_are_rejected_before_network_requests` 在旧代码得到错误的成功退出，修复后两文件入口、canonical／Unicode 形式均返回用法错误且零模型请求。

### R-03 P2 Todo 脱敏后失效却报告成功

- 位置为 [dispatch.rs](../crates/saya-core/src/dispatch.rs) 的 `todo_write` 派发。
- 合法清单脱敏后可能产生重复 ID，或使 ID／content 超过字符限制。旧实现仍保存 `ok=true`，但列表重建器拒绝该结果，界面和恢复沿用旧列表，模型收到的成功与实际状态不一致。
- 修复 `294e2fa` 在保存成功结果前复用 `result_todos` 校验脱敏后的清单。失败保存配对的 `invalid_args`，旧快照保持可用，模型可继续修正。
- 回归 `redaction_cannot_publish_an_invalid_successful_todo_snapshot` 通过真实 runtime 与 SQLite 覆盖 ID 碰撞、内容膨胀和 ID 膨胀，验证工具回传、后续请求及恢复一致。旧代码反例失败日志为 `target/review-todo-redaction-before.log`。

### R-04 P2 Responses 推理流与最终输出不一致仍成功

- 位置为 [responses.rs](../crates/saya-core/src/provider/responses.rs) 的 `StreamState::update`。
- reasoning／summary 增量只检查字符串，错误索引、item ID、done 文本、最终明文冲突或无替代的缺失仍可完成，界面 Thinking 与保存历史不一致，运行可继续派发工具。
- 修复 `fe408d1` 校验索引、可选身份、delta／done 及最终 reasoning 明文，在返回 Finished 前拒绝冲突。保留服务仅流式明文、最终非空 encrypted_content 的兼容路径。
- 回归 `reasoning_events_must_match_their_indices_identity_and_final_plaintext` 包含七组反例，旧代码第一组错误成功。已有仅 opaque 的兼容和历史重放回归继续通过。

### R-05 P2 TUI 外层错误收尾遗漏后台清理

- 位置为 [controller.rs](../crates/saya-tui/src/controller.rs) 的 `run` 出口。
- 终端错误使主循环提前返回，同时运行任务 panic／异常退出时，外层只取消并等待 JoinHandle，未调用后台 shutdown。仍由 RuntimeHandle 持有的后台任务可能继续运行，退出和会话锁释放先于进程清理。
- 修复 `727832b` 统一外层收尾，关闭输入／事件通道，等待运行任务，再无条件等待后台清理和 UI 任务，最后释放终端。
- 回归 `terminal_error_teardown_awaits_background_cleanup_after_runtime_panic` 使用真实后台进程及注入的运行任务 panic，核对进程消失和最终状态。确认依据为生产调用路径及该回归，首轮临时回退探针的编译失败未计为复现证据。

### R-06 P2 异步失败覆盖用户的新草稿

- 位置为 [services.rs](../crates/saya-tui/src/controller/services.rs) 的 `finish_ui`。
- 首条任务等待会话初始化期间，用户可输入另一份草稿。初始化或后续 prompt 交接失败时，旧代码直接将原任务写回编辑器，丢失新草稿。
- 修复 `727832b` 在空编辑器恢复原任务，有新草稿时保留编辑内容，并将原任务作为脱敏后的 Unsent draft 消息展示。
- 回归 `failed_initialization_preserves_a_newer_draft_and_the_unsent_prompt` 和 `failed_prompt_handoff_preserves_a_newer_draft_and_the_unsent_prompt` 验证真实初始化失败、交接失败、空编辑器、已知秘密及无误发送。

## 处置与验证边界

- 已确认六项问题均已修复。未在其余审查路径确认新的权限绕过、自动重复执行或数据库损坏问题，审查与现有回归的覆盖范围如上。
- 共享凭据检测仍采用失败关闭，重复键、过深嵌套和无法安全处理的数值可能使部分无秘密输入被拒绝。未知业务秘密超出当前已知配置值识别范围。
- 合法兼容响应仅在流中返回可读推理、最终只保存 opaque 时，当前界面可显示捕获的文本，恢复后无法由 opaque 重建该明文。
- 本轮使用本地模型夹具、临时工作区和合成凭据。未执行真实付费模型联调、新的远端工作流、跨平台或最低系统实测。历史 P7 和 RC1 `a6c172d` 的证据继续归属各自源码与平台，见[发行验证](release-validation.md)和[TUI 验证](tui-validation.md)。
- 运行任务异常后的 RuntimeHandle 不复用为新运行，界面按现有生命周期重建运行。丢弃 future 本身不保证清理，前端需等待显式 shutdown。
- 当前命令使用宿主权限，没有 OS Sandbox。进程组无法约束主动脱离的后代，SIGKILL、断电和物理终端断开仍有清理边界。Sandbox、MCP、自动 Compact、插件及模型可编辑全局记忆按[后续计划](post-mvp-plan.md)评价。
