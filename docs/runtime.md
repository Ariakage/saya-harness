# 可复用 Agent 运行时

**核心运行时、三协议、CLI、SQLite 恢复及事件输出已实现，0.1.0 已发布。当前开发线通过 saya-app 供 CLI 与默认 TUI 复用，各版本的平台与运行验证见[开发进度](progress.md)。**

`crates/saya-core/src/runtime.rs` 提供与终端无关的单次运行协调器 `AgentRuntime`。调用方提供 `RuntimeSetup`：会话对应的 `Run`、`Model`、`Store`、权限 `Policy`、已配置的 `ReadTools`、取消信号、核查与命令配置、单次预授权、用户任务摘要、可选人工确认回调以及运行预算。运行前获取 `RuntimeHandle`，可在运行期间请求模式切换或查看／取消本运行后台任务；运行结束后的旧句柄不可启动新任务。每次新运行或恢复均构造新的协调器，不复活历史授权。

运行协调器执行以下边界：

1. 检查会话身份、初始模式和保存状态；已保存会话与输入不一致时拒绝覆盖。
2. 按当前有效模式和权限构造英文 prompt、运行事实和可用工具 schema；调用 `Model`，完整响应后保存历史。
3. 对每个本地工具执行规则、独立模型核查或人工确认；运行时不重复保存由工具适配器负责的意图与结果。无效调用、拒绝、确认等待及未执行调用返回可配对结果。
4. 工具结果回到下一轮模型；共享模型／核查请求预算与活跃时间，控制工具次数、取消、超时、有限重试和重复失败。模式切换按调用边界生效；切入 PLAN 前后台写入与命令由任务管理器取消并清理。
5. 结束时停止新任务并等待后台清理；若结束时仍有未完成后台任务，`stop_reason` 标识 `completed_with_background_cleanup`。存储失败停止调度；已观察到的工具结果在适配器提供时通过 `BoundaryError` 保留。

`RuntimeHandle::background_events` 可读取本次运行内的后台生命周期快照：任务接受调度、取消请求及最终结果按单调序号排列。接受调度不表示工具副作用已开始；完成事件在执行调用返回后记录，结果保存失败会体现为失败，不能视为已持久化。该快照是内存中的控制信息，不等同于 P6 的持久化 schema-v1／JSONL 事件流。

接口由 CLI、TUI 等调用方复用。`Store` 的具体实现必须满足原子写入契约，仓库的 `MemoryStore` 用于受控测试。普通 CLI 已接入 SQLite、会话锁与中断恢复，并按权限规则执行真实工作区工具。用户取消通过 `Cancellation` 显式传入，调用方负责取消后等待运行和后台任务收尾。

前端在运行任务panic或被中止、JoinHandle已被消费时，可调用 `RuntimeHandle::shutdown_background().await` 停止新后台启动、请求取消并等待原有任务清理。该接口复用BackgroundJobs的关闭流程并返回清理错误，原有预算、取消和进程清理限额继续适用。TUI异常收尾先移除活动句柄、关闭通道并完成此清理，再返回错误和释放终端。

## 会话任务清单

开发线按D-046提供 `todo_write` 元数据工具，CLI与TUI共用运行时。模型对有多个实质步骤的任务维护完整列表，稳定ID对应 `pending`、`in_progress` 或 `completed`，最多一项处于进行中。静态工具提示词明确要求按实际结果更新进度，简单问答可直接完成。

调用格式为 `{"todos":[{"id":"inspect","content":"检查输入与现有实现","status":"in_progress"}]}`。每次成功调用整体替换列表，`{"todos":[]}` 清空。最多64项，ID最多64字符，非空内容最多500字符，输入JSON最多64KiB。工具返回结构化 `data.todos`，参数不完整或状态无效时返回 `invalid_args`。

列表从已保存的调用与成功结果按call_id配对重建，成功结果以脱敏后的内容为准。脱敏后仍须满足唯一 ID、字符和条目上限，冲突或超限返回 `invalid_args`，保留旧快照并允许模型修正。失败、拒绝、待批准和未成功保存的更新均不替换已保存列表。运行上下文的 `todos` 字段提供最新成功快照，恢复会话后可继续维护。

该工具操作会话元数据，PLAN可使用。auto允许默认元数据操作，显式规则继续判断，Manual Approval每次调用均需批准。许可绑定本次调用、参数、模式与权限版本，执行前后保存、取消和工具次数预算沿运行时统一处理。任务完成状态由模型报告，验收结果通过具体执行证据记录。

## 验证范围与后续

`crates/saya-core/tests/runtime.rs` 使用临时工作区、受控进程、内存／故障注入存储和模型替身，验证调用往返、12 种模式权限、确认、取消、模式切换、共享预算、重试、后台清理、历史闭合和保存失败。`./scripts/check.sh` 提供仓库级检查。

三协议的 HTTP／SSE 映射、provider 请求参数和离线协议夹具已有受控验证；CLI 交互和项目指令接入的具体证据见[开发进度](progress.md)。真实会话保存与跨进程恢复已在 P5 受控验证；JSON／JSONL 完整事件和已知凭据脱敏已有本机受控证据，指定模型完成有限抽样联调。当前接口仍非稳定 SDK。进程组清理不是操作系统沙箱，文件版本检查也不是对任意外部并发修改的原子比较交换。
