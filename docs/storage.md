# SQLite 存储组件

`SqliteStore` 在调用方指定的数据目录内创建 `sessions.sqlite3`。配置层的默认数据目录为 `$XDG_DATA_HOME/saya`，未设置时为 `~/.local/share/saya`；CLI 已接入会话创建和查询。新数据库采用私有文件权限，拒绝跟随数据库文件符号链接。

存储组件使用 bundled SQLite、WAL、`synchronous=FULL` 和外键；每批 `StoreChange` 在一个事务中提交，事务失败回滚。会话、完整历史、运行、工具意图／结果、确认请求、显式事件和关键状态变化日志分别保存。事件序号按会话持续递增；逐 token 文本 delta 不写入数据库。状态日志用于恢复与追踪，不等同于 P6 面向外部的完整 JSONL 事件。

调用者提供当前配置引用的凭据和请求头值。消息、工具参数／结果和运行结果在保存前遮蔽已知值及其常见 JSON 转义形式；无法安全遮蔽的关键标识、字段冲突和不透明签名状态采用失败关闭，避免破坏关联或签名。SQLite 不承诺识别未知秘密，也不会回溯清除以前不被识别的历史值。

共享脱敏会递归检查嵌套 JSON，包括 Unicode 转义。配置已知凭据后，重复对象键、解析递归超限、超出解析器数值范围，或脱敏重编码将改变数字表示的内容会失败关闭，避免遗漏字段或展示与实际操作不一致的数据。可安全解析且没有秘密的文本保留原文。

会话文件锁通过实际进程竞争及强制终止测试；不同会话可并行运行，查询不要求会话锁。数据库初始化也通过独立文件锁串行化。会话模式或工作区变更前先同步保守的安全检查点，变更事务完成后收敛为当前状态；崩溃时检查点保留所有可能位置，恢复前先检查 PLAN 目录，再打开数据库。旧会话若没有检查点，非空 WAL 使用校验帧和滚动校验和的内存快照，不创建或修改 SQLite 附加文件。旧会话快照的数据库文件和 WAL 各上限 512 MiB，超出时明确报错；正常新会话依赖小型检查点，不受此预检上限影响。

内部 schema 当前为 2。识别版本 1 后先通过 SQLite 在线备份生成独立文件、检查并同步到磁盘，再通过事务新增会话更新时间索引和更新版本；迁移失败保留原库与备份。版本更高或库损坏时拒绝打开。中断恢复将运行中的工具标记为 `unknown`，保留已保存的结果并原子补齐悬空协议消息；确认和输入中断不恢复授权，也不重放。后台启动意图先持久化，子任务使用可关联的标识，执行前保存子工具意图、执行后保存结果；会话详情可列出后台状态。恢复不重放任务，无法确认的结果标记为 `unknown`。强制终止 Saya 后后台子进程可能继续运行，未知状态不表示进程已停止；正常结束则等待清理。内存存储不会因本组件存在而成为持久存储。

每次执行模型请求的项目上下文来源元数据在请求前记入同一会话的状态日志：请求 ID、指纹和各来源的路径、作用域、类型及 SHA-256。记录不包含指令或 Skill 正文；持久化失败时停止该模型请求。旧会话可能没有此类记录。

机器事件与相应持久状态同事务提交后输出；可见文本 delta 不单独写库。事件序号按会话预留，重启后未使用的序号留空，不会复用。每次运行的执行／审核请求计数、工具次数、持续时间及可用 token 用量和显式费率估算也记录在状态日志；会话详情可查询。

## 只读导出快照

DEV-043 提供 `SqliteStore::read_snapshot`。稳定校验数据库与WAL后在内存image的单只读事务中取得所有集合，读取源文件时使用文件身份与限额校验，查询期间观察取消和期限。实际 MAX(change_log.seq) 与 MAX(events.seq) 作为持久水位，预留事件空洞保持原状。旧 schema 返回显式迁移提示，源文件及 SQLite 附加文件保持只读。

默认源总量128 MiB、规范化记录32 MiB、100,000行和5秒协作期限，调用者可通过 `SnapshotLimits` 选择更小或受支持的更大范围。导出先进行类型和关联校验，再按范围投影、脱敏和截断。格式与文件发布见[会话导出](session-export.md)。

## 后续上下文与输出存储

OutputStore、CompactionRecord 和 ContextView 属于[上下文设计](context-management.md)的后续增量。原始历史、模型请求投影、输出引用与摘要检查点分别保存来源和水位，新存储结构按版本化迁移与备份规则接入。当前实现状态以[开发进度](progress.md)为准。
